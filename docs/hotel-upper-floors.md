# ホテル Stage04

5Fと4Fを同じL字の外形から作成した試作ステージです。外寸は約55×40m、廊下幅は3m、階高は3.8mです。従来のホテルは `stage03` として開けます。

## 起動とルート

- Releaseではプロジェクトフォルダーで `Start-Game-Release.cmd --hotel-upper` を実行します。Debugのゲーム画面には **Open Upper Hotel (Stage04)** があります。
- **5F** は515号室から開始します。Eでドアを開け、向かいの横長のラウンジで試験用のSubを拾えます。ラウンジは旧514・516号室をつないだ約14×7.5mの空間で、縦廊下から直接出入りできます。513号室に1体、角の先に2体がステージ開始時からいます。横廊下の通行止めの手前で503号室に入り、仕切り壁の開口から504号室へ抜けて廊下に戻ります。横廊下の突き当たりにある階段を降り、下の踊り場から折り返すと4Fです。
- **4F** は階段を出て西へ。水色の印のある406号室のドアをEで開け、割れた窓から外へ出ます。幅約1.8mの足場は406号室から401号室まで続きます。404号室の開口部から戻るか、401・402・403・405号室のガラスを銃で割って出入りできます。403・404号室の廊下側のドアは初期状態で開いています。
- **東端の階段室** は5Fから1Fまで同じ位置でつながっています。4Fから3Fに降りる入口は瓦礫と梁で封鎖されています。2F・3Fは階段室と踊り場の構成です。
- **エレベーター** は両階ともL字の曲がり角の内側にあります。5Fの扉は閉鎖中です。4Fでは客室から廊下に戻って西に進み、エレベーターの奥に入ると武器・残弾・HPを引き継いで1Fに到着します。西端の旧エレベーター跡は廊下としてつながっています。
- **落下** は足元の支えを失ってからの落下距離が3mに達するとゲームオーバーになります。5Fから4Fの足場に落ちる場合にも適用します。階段を歩いて降りるときは床の支持が続きます。F7の配置テストでは落下死でテストが終了し、F8で編集へ戻れます。
- 4Fの火災は廊下の床を保持し、瓦礫・崩落梁・炎・煙と全幅のColliderで封鎖しています。物理判定、射線、敵の経路探索に同じ封鎖が反映されます。

## Blenderで編集

1. `Tools/blender/yanengine_level_exporter.py` の **YanEngine Level 1.17** をインストールして有効にします。
2. `resources/levels/stage04/stage04.blend` を開きます。初期表示は屋根を除いた **F5_Edit** です。右上の **F1_Edit〜F5_Edit** で各階だけを表示できます。1Fは Lobby、FrontDesk、Lounge、Service、Stairs、Elevator、Shutter、Breaches、Gameplay に分けています。
3. ドアは **Hinged Door** の箱メッシュです。オブジェクト原点を蝶番位置に置き、垂直に保ちます。**Open Angle** の符号で開く向き、**Initially Open** で開始時とRestart時の状態を指定します。ゲームでは箱の寸法から簡易ドアを描画し、回転するColliderと同期します。動作中にプレイヤーや生存中の敵が入ると、空くまでドアはその角度で待機します。
4. シャッター防衛の増援は **Enemy Spawn → Manual**、5Fの3体・4Fの1体・1Fの4体は **StageStart** です。F7のステージ一覧から `stage04` を選び、敵と武器の配置を試せます。
5. `Ctrl+S` で保存します。書き出し時は **ViewLayer** に切り替え、**N → YanEngine Level → レベルを検証 → レベルを書き出す** を実行します。Stage IDは `stage04`、Project Rootは `//../../../`、Output Directoryは `resources/levels/stage04` です。

5F・4Fのガラス窓は全30枚が破壊可能です。開口部を塞ぐガラスだけを独立したメッシュにし、**固定メッシュ → Collision: Box → Break on Bullet** を有効にします。銃弾が当たるとガラスの表示・衝突・経路判定が同時に消え、Restartで復元します。通常の窓には独立した窓枠と腰壁があります。シーンの **Fatal Drop Distance** で致命傷になる落下距離、**Fall Death Height** でゲームオーバーになる絶対高さを設定できます。

`stage04.json` はゲーム用のCollider・ドア・出現・ゴール情報、`stage04.gltf/.bin` は固定メッシュ、`stage04-layout.json` はF7用の階高と客室範囲です。壁の範囲を変更した場合、F7の部屋分類も変えるなら `stage04-layout.json` の該当範囲を更新します。初期ブロックアウトを作り直す `Tools/blender/create_stage04.py` は手編集済みのStage04を上書きするため、普段はBlenderの書き出しを使います。

## 1Fロビーと最終戦

1Fは40×30mの長方形で、主戦闘エリアは約28×21m、天井高5.4mです。受付カウンター、柱、待合のソファとテーブル、植栽と荷物を配置しました。到着用エレベーターはロビー北西の角にあり、扉と到着時の視点は東側シャッターを向きます。階段口、中央、受付、待合にステージ開始時から1体ずついます。

東側出口のスイッチをEで押すと30秒の防衛が始まります。シャッターは最後の3秒で巻き上がり、30秒で通行可能になります。そのまま出口を直進するとゴールです。残った敵を倒す条件はありません。

|防衛の出現元|位置と初回|
|---|---|
|階段|東端階段室の2F→1Fの段から北側連絡通路を経由、2秒|
|スタッフ通路|受付裏の西側、2秒|
|脇通路|待合奥の南東側、2秒|
|穴A|北側の中央寄りの壁、12秒|
|穴B|シャッター寄りの東壁、20秒|
|穴C|待合の南側にある壁、26秒|

各穴は開放時に壁パネルの表示・衝突が消え、瓦礫と鉄骨の間を通れるようになります。28秒には6か所すべてから出現します。仮設定は到着時4体、防衛中最大19体です。

1. 4Fの `F4_Elevator_Transfer` は **Stage Transfer** です。**Arrival Object** に1Fの到着マーカーを指定します。
2. 1Fの `F1_ExitShutter` でスイッチ、秒数、**Defend Before Opening** と **Progress Events (JSON)** を設定します。イベントの `progress` は30秒に対する割合、`spawnGroup` は起動する手動出現グループ、`openCollider` は開く壁パネルのIDです。
3. 防衛の各出現地点は既存の **Enemy Spawn → Manual** です。敵種類、出現数、同時生存上限を調整できます。穴パネルは **固定メッシュ → Collision: Box** で、出現イベントからIDで参照します。

## 検証と今後

`Tools/test-stage-loader.ps1` は5Fから1F出口までを移動とColliderで検証します。`Tools/test-upper-hotel.ps1 -Configuration Debug` または `Release` はGameSceneで到着、持ち物引き継ぎ、E操作、出現、穴の表示と衝突、ゴール、Restartを確認し、`generated/upper-hotel-tests` に結果と画面を出力します。

エレベーターは入室時の即時移動です。穴の演出はパネルが消える切り替えと固定の瓦礫・鉄骨で、音や落下する破片は今後の調整候補です。敵種・体数と遮蔽物はプレイテストに合わせて調整できます。
