# AI Live Development Phase 3

## ビルドと操作

`CG2_Setup.sln` を Visual Studio で開き、`CG2_Setup` をスタートアッププロジェクトにして **Debug / x64** で F5 を押します。PowerShell では `./tools/build.ps1 -Configuration Debug` で同じ構成をビルドできます。Lua 5.4.9 は `externals/lua/src` に同梱した C ソースから Debug x64 のゲームに静的リンクします。別途 Lua のインストールや配布 DLL は不要です。Development と Release のビルドには Lua を含めません。

同梱ソースの取得元は [Lua公式配布](https://www.lua.org/ftp/lua-5.4.9.tar.gz) です。SHA-256 は `2335b6c582a52654f94612bf10d2f4672805d05329aa6568b1d8cd9e5c6fb8e6` です。ライセンスは [MIT](https://www.lua.org/license.html) で、配布ソースの著作権と許諾は `externals/lua/src/lua.h` にあります。

1. タイトルから F6 で敵AIテストに入り、**AI Live Development → Lua 5.4** を開きます。直接起動する場合は Visual Studio のデバッグ引数に `--enemy-ai-test` を指定できます。
2. 敵を選択し、**選択中の敵の HP を半分にする**を押します。全AIの停止を解除して、敵の視認範囲にプレイヤーを置き、追跡を開始させます。
3. **Lua A → B → C → A** を順に押します。PID、敵のHP・AI状態、倍率、実際の移動を確認できます。速度が地形や攻撃範囲で制約される場合は、開けた場所で距離を取って試します。
4. `resources/LiveDevelopment/enemy-A.lua` などを編集中のゲームとは別のエディターで保存し、同じボタンを押すとファイルを再読込します。パネルの **現在のソースを編集 → Lua 変更案を反映** でも試せます。パネルでの編集は実行中の世代に適用され、サンプルファイルの保存はエディターで行います。

## API と制限

Lua テキストチャンクは `local enemy = ...` で値のコピーを受け取り、有限の数値 `0.0–3.0` を返します。入力は `id`、`type`、`hp`、`maxHp`、`state`、`distance`、前回の `speedMultiplier` です。HP はローカル部位と共有HPグループの合計です。距離はXZ平面で測ります。入力を書き換えてもゲームオブジェクトには伝播しません。AI状態は判断直前の値です。

Lua の実行環境に標準ライブラリやグローバルAPIを公開しません。入力テーブルと環境は呼び出しごとに作り直され、Lua固有の永続状態はありません。テキストは16 KiBまで、VMは256 KiBまで、1回の評価は2万命令まで、シーンの評価バッチは5万命令・約2 msを上限にします。期限はVMのフックで確認します。構文・戻り値・実行時の異常を候補検証で見つけた場合は現行世代を維持します。採用後に実行エラーが出た場合は、その世代の実行を停止し、そのフレームから全敵を倍率1.0に戻します。エラーは画面と操作履歴に1回記録します。

## 統合履歴

**変更をまとめて反映**で、最新DLL、Lua変更案、JSON変更案から適用する項目を選びます。各候補を検証し、履歴の保存に成功したら、シーン更新開始時に一括適用します。どれかが失敗すると全体を拒否します。Undo / Redoは操作単位です。敵が削除された場合や武器ランタイムの移行条件を満たせない場合は、複合操作全体と履歴位置を保持します。新規操作の成功時にRedo分岐を破棄します。

`generated/live-enemy-diagnostics/history.json` のPhase 2形式を引き継ぎます。Luaの変更には世代ID・ラベル・APIバージョン・ソースを保存し、DLL・Lua・JSONの変更前後と成否を同じ操作レコードに記録します。**変更履歴 → 差分**から、保持されている成功操作のLua世代を復元できます。DLL世代一覧とチェックポイントは従来どおり利用できます。Undo / Redoの操作位置はシーン内で最大16操作を保持します。

## 検証と Phase 4

`./tools/test-enemy-ai-scene.ps1 -CheckLivePhase3` で、実ゲーム内の速度測定、構文・実行・上限エラー、複合変更の全体拒否、Undo / Redo、DLLとチェックポイントの回帰、別プロセスでの履歴再読込を検証します。手動で実行エラーを試す場合はLua変更案に `while true do end` を入力し、反映が拒否されることを確認できます。

Phase 4では、ローカルエージェントから変更案を受け取る型付きインターフェース、対象シーンと世代の識別、同時要求と履歴衝突の扱い、適用結果と検証ログの返却、リプレイ中の適用方針が必要です。Luaに永続状態を導入する場合は状態スキーマと移行処理を追加します。
