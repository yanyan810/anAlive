# EnemySpawnの独立設定と起動方法

YanEngine Level 1.11.0以降では、新規の「敵出現地点」が出現内容を管理します。敵AI・行動・アニメーション・性能・種類は変更していません。

## Blenderでの設定

1. Emptyを追加し、オブジェクト種別を「敵出現地点」にします。
2. 「出現ID」を設定します。空欄ならオブジェクト名です。ステージ内の他の有効オブジェクトと重複できません。
3. 「敵の設定」を選びます。「1種類」は敵定義と総出現数を指定し、「種類ごとの体数」は敵定義と体数の一覧を指定します。
4. 「起動方法」「総出現数」「出現方式」「初回待機時間（秒）」「同時生存上限」を設定します。
5. 「レベルを検証」で確認してから「レベルを書き出す」を実行します。編集内容の保存はCtrl+Sです。

|起動方法|動作|
|---|---|
|ステージ開始時|トリガー不要。ステージ開始を0秒として初回待機時間の後に出現。待機0秒の敵はシーン初期化中に準備し、フェードイン中も時間を進めません。|
|トリガー起動|同じ「出現グループID」を持つ新形式トリガーが起動すると出現します。各地点の設定は独立しています。|
|手動・外部イベント|出現IDを共通APIへ渡して起動します。イベント編集UIは追加していません。|
|旧形式（互換）|既存ファイルの地点・重み付き敵抽選を維持します。出現内容は旧トリガーまたは既存の時刻指定グループが管理します。|

「総出現数」は1回の起動で出現させる総数、「同時生存上限」はその地点から出現した生存中の敵数の上限です。どちらも1～10000です。時間は0～1000000秒です。

1.12.0以降は「種類ごとの体数」で、同じ地点にNormal 3体＋Fast 2体などを指定できます。「敵の種類を追加」で行を増やし、各行の敵定義と「体数」を設定します。総出現数は自動的に合計5体となり、別の総数入力はありません。1行1～10000体、合計10000体までです。最初の切替時は現在の1種類の設定を1行目に引き継ぎます。

順次出現はリストの上から、通常3体、その後高速2体のように出現します。上下ボタンで順序を変更できます。同時出現は同じ更新で全種類を出現させます。同時生存上限は種類を合わせた上限で、待機した分の種類・体数・順序は維持されます。ステージ開始・トリガー・手動の全起動方法で利用できます。抽選の重みではなく確定した体数です。既存の「1種類」の設定や旧形式は変更しません。

- 順次出現：起動時刻＋初回待機時間で1体目、その後は出現間隔で出現します。間隔0秒も有効です。低フレームレートでは期限を迎えた分を同じ更新で出します。
- 同時出現：初回待機時間の後、空いている生存枠の分を同じ更新で出します。出現間隔は編集不可で、実行時も使いません。総数が上限を超える場合は残りを保持し、枠が空いた更新で出します。
- 生存上限待ちの間は出現間隔の遅れを蓄積しません。順次出現は枠が空くと1体出し、その後は通常の間隔で続きます。死亡した敵は生存枠から外れます。破片等が残る敵のプール返却は従来の回収条件に従います。
- 実行中の地点へ再起動要求を出しても途中からやり直したり、次の起動を予約したりしません。完了後の再起動は可能で、前回の生存敵も上限に含めます。

## 新形式のトリガー

オブジェクト種別「出現起動トリガー」で「トリガー方式」を「グループを起動」にします。

- トリガーID：空欄ならオブジェクト名。
- 出現グループID：起動する地点と一致させます。
- 起動条件：プレイヤー進入。範囲はCube Emptyの拡縮で編集します。
- 起動遅延：進入からグループを起動するまでの秒数。その後、各地点の初回待機時間が加わります。範囲から出ても予約は取り消しません。
- 一度だけ起動：ONならステージ中に1回。OFFならいったん範囲外へ出て再進入すると再起動できます。起動遅延の処理中は再予約しません。

トリガー欄には対象地点のID、総数、生存上限の一覧が出ます。新形式のトリガーに総数・間隔・生存上限はありません。

例：Aグループの地点01を総数3・同時出現・上限3、地点02を総数5・順次出現・間隔0.5秒・上限5にします。地点03をステージ開始時・総数2・同時出現・上限2にすると、開始時に03の2体、Aの進入時に01の3体と02の1体、その後0.5秒ごとに02の残りが出ます。

## JSONとC++ API

ステージのversionは1を維持し、spawnPointsに任意の独立設定を追加します。

```json
{
  "spawnPoints": [
    {"id":"Room308","position":[0,12,8],"rotation":[0,0,0],
     "activation":"OnTrigger","groupId":"A","enemy":"normal",
     "spawnCount":3,"mode":"Simultaneous","spawnInterval":0.5,
     "initialDelay":0,"maxAlive":3},
    {"id":"InitialGuards","position":[5,12,8],"activation":"StageStart",
     "enemy":"normal","spawnCount":2,"mode":"Simultaneous","maxAlive":2},
    {"id":"EventGuards","position":[10,12,8],"activation":"Manual",
     "enemy":"fast","spawnCount":5,"mode":"Sequential","spawnInterval":0.5,
     "initialDelay":1,"maxAlive":2}
  ],
  "spawnTriggers": [
    {"id":"HallwayA","position":[0,12,5],"size":[4,4,4],
     "groupId":"A","condition":"PlayerEnter","initialDelay":0,"oneShot":true}
  ]
}
```

`activation` がある場合、`spawnCount` と、`enemy` または `enemyComposition` のどちらか一方を指定します。種類別体数は次の形式で、spawnCountは合計と一致させます。

```json
"enemyComposition": [
  {"enemy": "normal", "count": 3},
  {"enemy": "fast", "count": 2}
],
"spawnCount": 5
```

modeの既定値はSequential、spawnIntervalは0.5、initialDelayは0、maxAliveはspawnCountです。groupIdはOnTriggerだけ必須です。アドオンは既存利用者との互換用にenemyPoolも出力しますが、独立起動の種類別体数はenemyCompositionを使って確定し、重み付き抽選は行いません。

```cpp
// シーン内のイベントから呼ぶ共通入口。シャッターなどには依存しません。
bool started = gameScene.ActivateEnemySpawn("EventGuards");

// スケジューラー単体を使う場合。
bool started = spawnSystem.ActivateSpawn("EventGuards");
size_t count = spawnSystem.ActivateGroup("A");
```

ID不明・旧形式・実行中ならActivateSpawnはfalseです。完了した独立設定の地点は起動方法にかかわらず明示再起動できます。ActivateGroupはOnTriggerの一致地点だけを起動し、実際に起動した地点数を返します。要求時に状態を起動し、敵の取得は次の出現更新で行います。ゲーム停止中は出現時間も止まります。

Stage Start／On Trigger／ManualはEnemySpawnSystem内の同じ地点別出現処理を使用し、GameSceneの同じコールバックからEnemyPool::Acquire → ResetForSpawnを通ります。通常の出現にEnemy::Initializeは追加していません。Resetとステージ再読込は予約・出現数・生存ID・トリガー状態・時刻・固定乱数状態を初期化します。デバッグ巻き戻しでは出現状態もコピーして復元します。

## 旧ステージの互換と移行方針

既存のJSON／blendは自動保存・一括書換えしません。旧blendは読み込み時にメモリー内だけで互換設定を識別します。

- `activation` のないJSON地点は従来どおり「位置＋敵抽選候補」です。勝手にStage Startにはしません。
- `groupId` のない旧JSONトリガーは共有総数・共有上限・Random／RoundRobin・間隔・初回待機・One Shotをそのまま使用します。複数地点へ総数をコピーせず、乱数の使用順も維持します。
- 旧blendを再出力しても旧schemaを維持します。Stage01～03の既存データは変更しません。
- 新設定へ切り替える場合は、地点の「起動方法」とトリガーの「トリガー方式」を明示的に変更し、地点ごとの総数・間隔・上限を設定してください。共有ランダム選択や共有上限は独立設定では完全に同じ挙動にできないため、自動分割しません。
- 同じグループに旧共有トリガーと新OnTrigger地点を混在させると検証エラーです。別のグループを使うか、グループ全体の設定を確認して切り替えてください。新旧トリガーのJSON項目の混在も拒否します。
- 既存の時刻指定SpawnGroupは仕様を維持します。同時出現はintervalを無視し、順次出現はtime＋行番号×intervalで出現します。既存グループの行別敵定義は地点の抽選候補に優先します。同じ地点を独立起動と時刻指定の両方で使うと、それぞれから出現するため、意図した設定か確認してください。
- タイトル・Showroomの既存の専用出現経路は維持します。付属ステージ生成スクリプトも旧形式を明示し、再生成による自動出現の追加を防ぎます。

## 検証

```powershell
./tools/test-blender-spawn-activation.ps1
./tools/test-blender-level.ps1
./tools/test-blender-spawn-groups.ps1
./tools/test-stage-loader.ps1
./tools/build.ps1 -Configuration Debug
./tools/test-enemy-pool.ps1
./tools/build.ps1 -Configuration Release
```

新しいBlenderテストはStage01～03の旧設定を別プロジェクトへ出力して一致を検査し、元のステージ全ファイルのハッシュを確認します。新形式の設定・実際のRNA入力制限・Validate・定義メニュー・保存再読込・エクスポートは `generated/spawn-activation-tests` で検証します。C++テストは3方式・地点別総数・低フレームレート・遅延・上限待ち・再起動・旧形式を検査し、D3Dテストは実GameSceneでプール再利用・レンダラー再初期化なし・巻き戻し・Restartを確認します。

対象外のAI・アニメーション・性能変更、敵種類追加、ランダム総数、Box/Radius出現範囲、シャッター開放率イベント、イベント編集UIは追加していません。
