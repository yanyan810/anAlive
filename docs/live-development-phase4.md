# AI Live Development Phase 4

## Windows 11 で起動する

1. [Ollama の Windows 版](https://docs.ollama.com/windows)を手動で導入します。起動済みのトレイ版がある場合は終了してから、ローカル専用で起動します。

   ```powershell
   $env:OLLAMA_NO_CLOUD = '1'
   $env:OLLAMA_HOST = '127.0.0.1:11434'
   ollama serve
   ```

2. 別の PowerShell で最初のモデルを取得し、接続を確認します。

   ```powershell
   ollama pull qwen2.5-coder:3b
   ollama list
   Invoke-RestMethod http://127.0.0.1:11434/api/tags
   ```

3. Visual Studio で `CG2_Setup.sln` を開き、`CG2_Setup` を Debug x64 で F5 実行します。タイトルで F6 を押して敵AIテストへ入り、敵を選択して **AI Live Development → ローカル AI チャット** を開きます。デバッグ引数 `--enemy-ai-test` で直接起動することもできます。

4. **Ollama 接続設定**でモデル名、接続先、タイムアウトを変更できます。ゲームは初期値として `http://127.0.0.1:11434`、`qwen2.5-coder:3b`、45 秒を使用します。設定変更はシーン内で有効です。

3B の配布サイズは約 1.9 GB、比較候補の 7B は約 4.7 GB です。実行時はモデルの重み、文脈キャッシュ、実行バッファとゲームがGPUメモリを共有します。RTX 3070の8 GiBを想定して3Bを暫定値にしています。Windows 11 / Visual Studio 2022 の v143 が対象です。検証環境では v143 を Visual Studio 2026 から使用しました。[モデル一覧](https://ollama.com/library/qwen2.5-coder) · [ローカル専用設定](https://docs.ollama.com/faq)

実モデル比較では、3B と 7B で下記の4指示を各3回試し、送信から検証済み表示までの時間、成功件数、実際の追跡速度と GPU メモリを記録します。稼働中のモデルの `size_vram` は `Invoke-RestMethod http://127.0.0.1:11434/api/ps` で確認できます。ゲーム実行中の合計は `nvidia-smi` で確認します。[Ollama 稼働モデルAPI](https://docs.ollama.com/api/ps)

## チャットと承認

例えば以下のように指示して **送信** を押します。

- 敵のHPが50%以下になったら1.5倍速にして
- 追跡中だけ2倍速にして
- HPが30%以下で追跡中なら2.5倍速にして
- 通常の移動速度に戻して

AIには選択中の敵の状態、現在のLua、利用可能な操作、対象とベース世代を送ります。今回の操作は選択した Spawn ID に限定されます。ほかの敵には従来のLuaが適用されます。攻撃追加などの対象外操作では理由が表示されます。

**確認**モードは検証済みのコードを表示し、**承認して反映**を待ちます。**標準**は既定値です。**標準**と**自動実行**では検証済みの許可操作を自動反映します。AI応答が確認を要求したときは、この2モードでも承認を待ちます。指示の先頭の `/確認 `、`/標準 `、`/自動 ` で今回だけ指定できます。全モードで同じ対象・操作・Lua制限が適用されます。

**動作確認**は「人間が確認」が既定です。「共同確認」と「AI が確認」は確認方針として記録し、状態に加えて最近の操作結果を最大4件送ります。画面認識とゲーム入力は手動です。

## 反映の境界

Ollama プロセスが推論を実行し、ゲームのHTTPワーカーがループバックの `POST /api/chat` で構造化応答を受信します。プロキシとHTTPリダイレクトを無効にしています。ゲームのメインスレッドは応答の確認と、Phase 3の境界での検証・適用を担当します。DebugAIViewerは従来のNamed Pipeを使います。AIチャットはリプレイの記録または再生中に要求を破棄します。[Ollama Chat API](https://docs.ollama.com/api/chat) · [構造化出力](https://docs.ollama.com/capabilities/structured-outputs)

操作種別、シーン、敵、ベース世代、項目の型を照合し、Luaを既存の隔離VMでコンパイル・試行します。Luaに許可される戻り値は有限の速度倍率 0.0〜3.0 です。適用直前にも対象と世代を確認し、途中で選択、シーン、DLL・Lua・JSONの適用世代が変わった提案は再送信が必要です。キャンセルするとHTTP要求を閉じ、後から届く応答を破棄します。

AI生成Luaは `local enemy = ...` で始め、読み取り専用の入力として扱います。速度倍率は `enemy.speedMultiplier` へ代入せず、すべての分岐で数値を返します。システムプロンプトにはフィールドの型と、HPによる分岐・`Chase` による分岐の例を含めます。操作名はJSONメタデータです。対応操作の説明は短い定型文とし、説明欄の上限は120文字です。

Luaの検証エラー時は、元の指示と失敗候補、エラーの種類と原文、修正条件をOllamaに渡します。初回と修正2回の最大3試行で、候補の再送または同一診断の繰り返しを検出した場合は打ち切ります。JSONや対象の不一致、途中で打ち切られた応答、通信失敗ではその要求を終了します。確認モードや候補からの承認要求は修正後も引き継がれます。チャットには試行番号、最後のエラー、最新候補が表示され、**AI 実行履歴**には試行ごとの候補と検証結果が残ります。検証ログはUndo対象になりません。

成功した変更は操作ID付きで `generated/live-enemy-diagnostics/history.json` に記録します。Undo / Redoは既存ボタンまたは Ctrl+Z / Ctrl+Y を使用します。Luaの上書きは同じシーンの生存期間内で最大8体です。シーン退場で解除されます。採用後に初めて起きた実行エラーでは、対象の上書きを停止し、直前の対象ルールまたは元のLuaに戻します。それもその入力で失敗した場合は倍率1.0で継続します。

## テスト

PowerShell 7 で `./tools/test-live-ai-chat.ps1` を実行すると、ローカルHTTPの模擬OllamaとDebug x64のゲームを起動します。戻り値なし・入力の束縛なし・構文エラーの修正、試行上限と途中キャンセルを検証します。 `-RealModel` では、起動済みOllamaの `qwen2.5-coder:3b` にHP条件と追跡条件を問い合わせ、報告された2件の失敗コードを初回候補として与えた修正テストも行います。Phase 1〜3の回帰には `./tools/test-enemy-ai-scene.ps1 -CheckLivePhase3` を使用します。

F5での手動確認では、全AIを一時停止した状態で敵のHPを半分にし、チャットで変更を送信します。その後AI停止を解除し、追跡中の倍率と実際の移動を確認します。確認モードでは承認前に倍率が変わらないこと、シーン移動中の応答を次のシーンに持ち越さないことを確認します。

次の段階では実モデルごとの日本語生成精度とVRAMを計測し、読み取り専用の調査機能、複数ファイルへの提案、適用前のテスト計画、外部エージェント向けのセッション境界を追加できます。
