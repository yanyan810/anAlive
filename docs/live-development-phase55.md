# AI Live Development Phase 5.5

`Debug | x64` の敵AIテストで **AI Live Development → ローカル AI チャット → プロジェクト調査** を選ぶ。質問の回答には、主張ごとの確認状態と `E1` などの根拠IDが表示される。根拠を開くと相対パス、実際の行範囲、抜粋を確認できる。既定の調査ステップ上限は8。

## 根拠の確認

- 遮蔽、部位破壊、武器ダメージ、敵AIの更新、Spawn Group、敵AIテストのLua反映は、関連する分岐や呼び出しのトークン列を実ソースの抜粋と照合する。例えば、壁の `Raycast` が `blocked` を作り、それが視野・視認距離とともに `visible` の条件に入ることを確認する。部位破壊はループ内の早期 `return true` とHPの条件をまとめて照合する。
- 検証した主張には、その判断に必要なファイルと行範囲を対応付ける。公開前に、相対パス、行範囲、SHA-256、抜粋をディスク上のファイルと再照合する。Ollamaが返したIDは、今回提示したIDから照合する。既知の矛盾を検出した場合はUIに表示する。
- その他の質問では既存の検索と追加読み取りを使う。モデルが見つけた箇所から文脈を読み、ホストが意味を確認できない主張は **未確認** と表示する。部分的な調査で機能の不存在は断定しない。ステップや送信量に達したら上限を表示する。
- この確認方式は現在の構造に対応する限定的な規則。C++全体の構文解析・実行経路の証明には別の手段が必要になる。規則に合わない変更では、対応する主張が未確認になる。

## モデル比較

PowerShell 7で実行する。2周の既定値で8問を同じ順序で試し、Q8はQ2の追加質問として扱う。

```powershell
./tools/build.ps1 -Configuration Debug
./tools/test-live-ai-chat.ps1 -Research
./tools/compare-project-research.ps1 -ColdLoad
```

比較は `127.0.0.1:11434` に導入済みの3B・7Bを対象にする。`-ColdLoad` は測定対象モデルをすでに読み込んでいる場合に解放し、初回リクエストのロード時間と2周目の応答時間を記録する。両モデルの温度、コンテキスト長、生成上限、反復ペナルティは共通。検証規則で読む質問には同じ抜粋を使い、通常検索の根拠はモデルが選ぶ。採点用データの正解・許容表現・誤答条件は、モデルに渡す質問ファイルから除外する。

結果は `generated/project-research-benchmark/日時/report.json` と `report.md` に保存する。JSONにはモデルの生回答、表示した結論、主張と根拠、各質問のステップ数、Ollama報告のロード・推論時間、経過時間、VRAM、FPS、最大フレーム時間、状態保持、Gitコミットと作業ツリーの変更有無を含める。自動判定は根拠範囲と鮮度、ホスト検証、状態保持。生回答の意味の正誤は質問セットの基準で別に採点する。VRAMはGPU全体のサンプル値、FPSは実D3Dのベンチマークループ、物理入力から描画までの遅延は未計測として記録する。

7Bを導入する場合のコマンドは `ollama pull qwen2.5-coder:7b`。モデルファイルの公称サイズは約4.7 GB。 [Ollamaのモデル一覧](https://ollama.com/library/qwen2.5-coder/tags)

## Phase 6

編集案の根拠には、対象範囲とファイルの版に加えて、成立を確認した条件、未確認の呼び出し経路、再現テストの結果を添える。承認時と適用直前にSHA-256で競合を確認し、ソース編集履歴と実行時変更履歴は操作IDで関連付ける。モデルによる説明は差分の承認や実行権限の代わりにはならない。
