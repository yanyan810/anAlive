# AI Live Development Phase 5

Visual Studio の `Debug | x64` でリポジトリを作業ディレクトリとして起動し、敵 AI テストの **AI Live Development → ローカル AI チャット** で **プロジェクト調査** を選ぶ。Ollama が動作していて `ollama list` に `qwen2.5-coder:3b` があれば、既定の `http://127.0.0.1:11434` ですぐに質問できる。

- 「EnemyAI の更新処理はどこですか？」のように質問して **調査する** を押す。回答の `相対パス:開始行–終了行` を開くと、根拠になった行が見える。
- 「その処理で壁は考慮されていますか？」のように続けて聞ける。最新の6件・40 KBまでをシーンのメモリに保持し、「その」「先ほど」などで始まる質問や短い質問には、直近3件・3 KBまでの文脈を調査時に添える。**会話を消去** で消去できる。
- **調査上限** でステップ数、結果数、取得行数、総送信テキスト量、全体タイムアウトを設定できる。既定は5ステップ、6結果、48行、24,000バイト、90秒。接続設定のタイムアウトは個々の HTTP リクエストに適用され、調査全体にも別途期限がある。
- **調査をキャンセル**、シーン退出、チャット用途の切り替えで調査を破棄する。**Lua変更** に切り替えると実行時の変更パネルを操作できる。

## 調査操作

| 操作 | 入力と結果 |
| --- | --- |
| `search_files` | ファイル名・相対パスの部分一致。任意で相対ディレクトリと拡張子を指定する。 |
| `search_text` | テキストのリテラル一致。任意で相対ディレクトリまたはファイルを指定する。 |
| `find_symbol` | 識別子の境界を考慮したテキスト一致。宣言・呼び出し候補にヒントを付ける。結果はいずれも `text_match`。 |
| `read_file` | 相対パス・1始まりの開始行・行数を指定して UTF-8 の抜粋を取得する。 |

Ollama は各応答で1つの操作を選ぶ。ホストが JSON を検証して調査を実行し、次のリクエストに質問と必要な結果を付ける。検索が確認した相対パスを行読み取りの候補とし、同じ操作・引数の繰り返しを抑える。根拠にはホストが ID を割り当て、回答に使われた ID が直近のリクエストにあり、ディスク上の SHA-256 が一致することを確認してからパス・行範囲を表示する。過去の回答に表示する抜粋は当時の記録。モデルによる処理の解釈は、表示されたソースと照合できる。

調査と通信はワーカーで処理する。DebugAIViewer と共通化したのは、ソース走査からビルド・依存物ディレクトリを除く判定。Viewer は従来の索引と Named Pipe を使う。調査の会話は DLL・Lua・JSON の適用履歴から独立している。

## 調査範囲と情報保護

- 読み取り対象は、プロジェクトルート配下の C/C++、Lua、JSON、CMake、Visual Studio 設定、Markdown。`generated`、依存物、キャッシュ、隠しパス、秘密情報を示す名前などを除外する。
- 絶対パス、`..`、代替データストリーム、再解析ポイント、複数のハードリンクを持つファイルを拒否する。開いた Windows ハンドルから実ファイルのパスを取得し、ルートと拡張子を再検証する。
- 認証情報を示す代表的なキー名やトークン形式を検査し、検出したファイルは名前も抜粋もモデルに送らない。未知の形式の機密情報には検出漏れがあり得るため、機密情報は調査範囲外で管理する。
- 通信はプロキシ・リダイレクトなしの IPv4 ループバックに限定する。ソースの送信前に Ollama のモデル情報を確認して、ローカル GGUF を要求する。接続先には自身が管理する Ollama を使う。Ollama 自体のクラウド機能も無効にする場合は、Ollama 起動時に `OLLAMA_NO_CLOUD=1` を設定する。[モデル情報 API](https://docs.ollama.com/api/show) · [Ollama FAQ](https://docs.ollama.com/faq)
- 1ファイルは2 MiB、1走査は6,000項目・約24 MiB、1行の抜粋は1,000バイト、1回の抜粋は4,500バイトまで。大きな範囲は行を分けて調査する。ファイルは要求のたびに読み取る。

## 検証

```powershell
./tools/test-live-ai-chat.ps1 -Research
./tools/test-live-ai-chat.ps1 -Research -RealModel
./tools/test-live-ai-chat.ps1
./tools/test-enemy-ai-scene.ps1 -CheckLivePhase3
```

F5で手動確認する場合は、敵 AI テストで調査を開始してから TAB でカメラ操作に切り替え、ゲームの入力・描画が続くことを確認する。チャットに戻り、検索操作、回答、根拠の行を開く。続けて質問を送り、調査中にキャンセルするか、F6でタイトルに戻って結果が持ち越されないことを確認する。

## Phase 6 の設計案

ファイルごとに相対パス、現在の SHA-256、変更する行範囲、置換テキストを持つ変更案を作る。操作 ID で複数ファイルを束ねて、ユーザーに全差分を提示する。承認直前と書き込み直前にハッシュを照合し、競合時は再調査する。承認された変更だけを別の編集サービスで一括適用し、途中失敗時は元のファイルを復元する。

ソース編集履歴には変更前後のハッシュと復元に必要な内容を保存する。ソースの Undo / Redo でも現在のハッシュを照合する。ビルドは許可したプロジェクト・構成で別ジョブとして起動し、コンパイル結果を操作 ID に結び付ける。ホットリロードできる成果物は既存の実行時変更管理へ渡し、ソース履歴と実行時履歴を操作 ID で関連付ける。
