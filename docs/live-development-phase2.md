# AI Live Development Phase 2

Debug x64 でリポジトリを作業ディレクトリにしてゲームを起動します。タイトルから F6 で敵AIテストへ移動し、Esc でマウスを解放して左の **AI Live Development** を開きます。

## DLL の切り替え

1. ゲームを開いたまま、PowerShell で `./tools/build-live-enemy-diagnostics.ps1 -Variant A` を実行し、**最新 DLL を反映**を押します。
2. B、C を順にビルドして同じボタンで反映します。B では脅威度、C では視認距離が診断の詳細行に表示されます。画面の PID、敵 ID、位置、HP を比較するには全AIを一時停止しておきます。
3. **Undo → Undo → Redo** で C → B → A → B になることを確認します。左の設定パネルにフォーカスがあり、入力欄やポップアップを使用していない UI 操作モードでは Ctrl+Z / Ctrl+Y も使えます。JSON 入力欄では通常のテキスト編集ショートカットが使えます。
4. B で D を反映すると Redo は消えます。**DLL 世代一覧**から C を復元できます。任意復元は現在位置に新しい変更を追加します。ゲームを終了して起動し直しても、一覧から過去の世代を復元できます。

履歴はリポジトリ内の `generated/live-enemy-diagnostics/history.json` に UTF-8 JSON で保存します。スキーマは 1 です。正常な世代には GUID、DLL/PDB の SHA-256、UTC ビルド日時、Variant、ABI を記録します。操作には種類、成否、日時、概要、変更前後の値、チェックポイントの結果が入ります。ビルド時に世代ディレクトリへ `generation.json` を書き、`latest.json` を置き換えます。Phase 1 の `latest.json` も読み込めます。旧成果物の Variant は不明と表示し、日時は DLL の更新時刻を使用します。

世代一覧は 32 件、操作ログは 64 件、Undo / Redo はシーン内で 16 状態を保持します。再入場・再起動時は組み込み表示から開始します。更新中の DLL はファイルをロックし、候補は DLL/PDB の存在、ハッシュ、エクスポート、ABI、診断出力を確認してから切り替えます。履歴への保存に失敗した場合も、現在の DLL と Undo / Redo の位置を保持します。DLL 内のネイティブ例外やメモリ破壊はプロセスに影響し得るため、自分でビルドした DLL を使用してください。

ゲーム終了後、`./tools/prune-live-enemy-diagnostics.ps1` で削除候補を確認できます。`-Apply` を付けると、最新公開・履歴から参照される世代を除き、未参照の新しい 8 世代を残して削除します。 `-KeepUnused` で件数を指定できます。マニフェストがない Phase 1 成果物はスクリプトの対象外です。

## チェックポイント

**状態を保存**し、移動や視点変更をしてから**保存した状態を復元**を押します。スキーマ 1 のチェックポイントはシーン内のメモリに保持します。プレイヤーの変換・HP・移動・武器の現在値、カメラの位置・向き・FOV、敵の Spawn ID・位置・部位 HP・共有 HP・AI・顔面破片、発射済み敵弾、出現位置・次の ID・敵選択・一時停止・無敵設定を扱います。チェックポイントは既存の敵構成に復元します。敵の追加・削除で構成が変わった場合や、分離モデル片がある場合は復元を拒否します。状態ペイロードにはモデルの生ポインタを含めません。

DLL の切り替え前には状態をキャプチャ・検証し、既存のインスタンスを維持します。通常の切り替えではチェックポイントを復元しません。手動で保存したチェックポイントがある間はそれを復元対象にします。履歴 JSON には作成・検証・復元の結果を記録します。復元時は現在の索敵・武器定義を維持し、現在の武器定義へ装弾・タイマーを移行できる場合に復元します。

## JSON の即時反映

- **選択中の敵の索敵設定を開く**で、その敵の `viewDistance`、`fieldOfView`、`detectionTime`、`loseSightTime` を編集できます。変更案の対象は開いた時点の Spawn ID です。
- **武器定義を開く**で `resources/Data/weapons.json` の `weapons` を編集できます。テストシーンでは定義の初期武器かピストルを使用します。装備の ID と弾数・残りタイマーを引き継ぎ、容量を下げた場合は上限で切り詰めます。リロードやバースト中の互換性のない変更は拒否します。パネルで装弾消費とリロード開始を試せます。
- **検証**で構文・値・移行条件を確認し、**実行中のゲームへ反映**で再検証して次のシーン更新時に適用します。構文エラー、重複キー、範囲外の値、対象消失、履歴書き込み失敗では現行値を保持します。**変更履歴 → 差分**で成功した反映の差分を確認できます。元の JSON を保存するには既存エディターを使用します。

## 検証

`./tools/test-enemy-ai-scene.ps1 -CheckLivePhase2` は実ゲームのプロセスで DLL の切り替えと拒否、チェックポイント、JSON を検証し、別プロセスで履歴を再読込します。テスト用のマニフェストと DLL は `generated/live-phase2-tests` に作成します。通常の敵AIテストには `./tools/test-enemy-ai-scene.ps1 -Configuration Release`、FPS 本編のスモークテストには `./tools/test-enemy-ai-stages.ps1 -Configuration Debug` を使えます。

ImGui の手動確認では DLL 世代表示、設定パネルにフォーカスしたときの Ctrl+Z / Ctrl+Y、JSON 入力中のテキスト Undo、FPS 操作中に DLL が切り替わらないことを確認します。DebugAIViewer ではゲームへの接続、記録、再生を確認します。

## Phase 3

Lua の変更を追加する際は、操作の `changes` 配列にスクリプト・設定をまとめ、全候補の検証を終えてから単一の更新境界でコミットします。スクリプトの状態移行、命令・時間の上限、例外時の旧状態への復帰、再生中の切り替え方針が必要です。Development x64 への導入時は、Debug 専用のホストとシーンフックを共通の開発ビルド条件にそろえます。
