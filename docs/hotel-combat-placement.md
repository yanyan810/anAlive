# ホテルの武器・敵配置

`Start-Game-Release.cmd` → GAME STARTで開始。F7から各配置を編集できます。

|場所|配置|
|---|---|
|3階・308リスポーン室|Sub、レア度1～2の武器を1個。Pistol / Grog / Revolver / double_shotgunが候補|
|3階・301～307|Normalを各1体、計7体。304には客室サイズのTankも1体。全8体を各室の通路側の出入口へ向ける。308には敵を置かない|
|2階・大広間前の前室|Main、レア度2～4の武器を1個（中央）|
|2階・大広間|Normalを7体。ステージ開始時から配置|
|1階・出口シャッター手前|Main、レア度3～4の武器を3個|
|1階・増援出現地点7か所|シャッター操作から10秒ごとにNormal6体＋ランダム別種1体。10～60秒の計6回|

武器は各地点の条件から抽選します。同じ種類が複数地点に出ることもあります。敵が通常の視界・発見待ち時間でプレイヤーを確認すると、その敵と、発見した敵の索敵距離内（`senses.viewDistance`）で間に壁がない仲間が継続追跡を開始します。2階の全員への一括共有は廃止しました。範囲外や壁・床・天井で隔てられた敵には、その発見を伝えません。伝達を受けただけの敵は、見えていないプレイヤーの発見を周囲へ中継しません。自分でプレイヤーを目視した敵は新しい発見元になれます。発見した本人と伝達を受けた仲間は、視界を失ってもプレイヤーの現在位置を追います。

1階のシャッター増援7地点は `pursueOnSpawn: true`。出現直後からプレイヤーを追跡し、壁は既存の経路探索で回り込みます。追跡指示があっても、壁越しの近接攻撃・射撃は行いません。初回の発見は従来どおり視界・認識時間で判定します。追跡指示を出す際も目視の記録を偽造しません。F7の詳細設定で出現時追跡を編集できます。

通常の目視発見でも共有AI自身が継続追跡を保持するため、本編以外のF6でも一度発見した敵は壁・視野外・距離・時間経過で未発見に戻りません。発見後の進捗表示は100%を維持します。死亡で行動を止め、リセット・再出現・ステージ再開始で認識を初期化します。詳しくは [enemy-ai-test.md](enemy-ai-test.md) の現在の追跡仕様を参照してください。

初期の敵は計15体、武器は計5個です。増援は最大42体（倒さなければ合計57体）。別種枠はFast / Ranged / Tank / Bomberの等確率抽選です。

現在のすべてのSub武器に `infiniteReserveAmmo: true` を設定しました。装弾数は通常どおり減り、空撃ち・射撃間隔・リロード時間は維持します。Magazine / PerRoundとも予備弾を消費せず補充します。HUDの例は `12 / 12 RES INF`。Mainの予備弾は有限です。既存のタイトル用「マガジンも減らない無限弾」とは独立した設定です。Weapon EditorのAmmoタブで切り替えられます。

304のTankは `hotel_tank` 定義で高さ2.7mに調整し、横幅・耐久力・攻撃力を維持しています。他のTankの大きさは維持します。

シャッターは60秒で全開。`shutters[0].enemyWaves` の `groupId: hotel_shutter_wave`、`interval: 10` がManual出現地点7か所を起動します。各地点の最大生存数は6で、敵を倒さなくても6回分を出現できます。全開になる60秒時点も出現し、その後は停止します。ポーズ中は進まず、クリア・死亡後は増援を生成しません。再開始で状態を初期化します。長いフレームで複数回分の時間が進んでも、出現回数を落としません。

配置データは `resources/levels/stage03/stage03.json` と `enemy_placements.json`、階層・部屋ラベルは `editor_metadata.json`。以前の配置と武器定義を `generated/hotel-combat-before/` に保存しました。.blendは変更していないため、Blenderから再出力するとステージ側の設定はBlenderの内容に置き換わります。

検証：`tools/test-weapons.ps1`、`tools/test-hotel-combat-placement.ps1 -Configuration Debug`（Releaseも同様）。実GameSceneで初期15体、3階Tankの寸法・8体の出入口への向き、発見元の索敵距離・壁による伝達制限、壁の向こうと範囲外の敵が待機すること、目視していない近傍の仲間の移動・7秒間の継続追跡・ホテルの壁への非侵入、1階増援の即時追跡と実移動、全配置の床・壁・天井、5武器の条件・再取得と交換落下・残弾復元、10～60秒の各回7体とランダム別種、全開後の停止、ポーズ・リトライ・長フレーム追従、GPU描画を確認します。画像と結果は `generated/hotel-combat-tests/<Configuration>/` に保存します。

階段での追跡停止を修正しました。経路・足元の高さ・複数体の検証は [enemy-stairs.md](enemy-stairs.md) を参照してください。

配置された武器は取得後もその場に残り、同じ抽選済みの種類を何度でも拾えます。交換時に持っていた武器は床上に落ち、武器の定義・装弾数・予備弾数を個別に保持します。落とすとリロード／残りバーストは中断し、拾い直しても補充されません。交換で落ちた武器は配置元とは別の実物で、取得するとその場所から移動します。ステージ再開始で落とした武器は消え、初期配置に戻ります。

2階の階段ロビーから大広間への入口（X=12、Z=8.4～11.6）は壁で封鎖しました。旧 `F2_Ballroom_West_Lintel01` を床Y=6から天井下面Y=11.65まで延長し、Collider・glTFのPOSITION境界・実際のbin頂点をそろえています。武器のある前室側の入口（Z=26）は維持し、3階→前室→大広間→東階段→1階の経路を通れます。接続情報も `stage03-layout.json` に反映しています。.blend自体は変更していません。

開始時の装備はなし（`weapons.json` の `initialWeapon: ""`）です。リトライ時も手ぶらに戻ります。308のSub配置は維持しており、Eで拾うと装備します。最初の取得では交換前の武器がないため、空の武器は落ちません。
